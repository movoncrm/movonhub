# MOVONHUB Internationalisation (i18n)

## Languages

| Code | Language | Role |
| --- | --- | --- |
| `en` | English (en-MY) | **Default** |
| `ms` | Bahasa Melayu (ms-MY) | Secondary |

A fresh visitor gets **English** (per the dark landing page brief). The choice is persisted in a
cookie (`mh_lang`, 1 year, `SameSite=Lax`) and survives navigation and future visits. The header
toggle is ordered **EN | BM**. The advisor microsite supports both languages unchanged.

## Architecture

```
src/i18n/
  config.ts   locale list, default, cookie name, type guards
  ms.ts       Bahasa Melayu dictionary (canonical shape + `Dictionary` type)
  en.ts       English dictionary (typed against the ms shape)
  index.ts    pure helpers: dictionaries, getDictionary, translate, interpolate
  server.ts   server-only: getLocale(), getI18n()  (imports next/headers cookies)
```

- `index.ts` is **client-safe** (no `next/headers`).
- `server.ts` is **server-only** and reads the cookie.

### Server components

```ts
import { getI18n } from "@/i18n/server";
const { locale, dict, t } = await getI18n();
t("nav.products");                       // "Produk"
t("success.subtitle", { name: "Nik" });  // interpolation
```

### Client components

```tsx
"use client";
import { useI18n } from "@/components/i18n/LanguageProvider";
const { locale, dict, t, setLocale } = useI18n();
```

`LanguageProvider` is mounted once in `src/app/layout.tsx`, seeded with the
server-resolved locale. `LanguageToggle` (in the navbar, footer and auth/advisor
headers) renders the **BM | EN** control.

### Switching without a full reload

`setLocale` writes the cookie, updates client context immediately, then calls
`router.refresh()` so server components re-render with the new cookie. There is no
full page reload and no hydration mismatch (the server and the client start from
the same locale).

## Keys

- Dot-path lookup with fallback to the key string (surfaces missing keys during dev).
- Interpolation via `{placeholder}`.
- `en.ts` is typed as `Dictionary` (`typeof ms`), so **additions to `ms.ts` force a
  matching key in `en.ts`** — a test also enforces key parity.

## Rules applied

- **No "anda"** in Malay copy (enforced by a test scanning all `ms` values).
- Brand names, product names, model numbers and URLs are never translated.
- Database-driven proper nouns (product names, category names, advisor bios,
  promotion titles) stay as stored; UI chrome, headings, buttons and messages are
  translated.
- Malay uses natural Malaysian phrasing without second-person pronouns.

## Coverage

Translated: navigation, footer, homepage, catalogue, product detail, advisor
directory, advisor microsite, registration, login, success, dashboard, admin
portal, tools, MOVONHUB AI, forms, empty states, messages, SEO metadata and
accessibility labels.

## Adding a language

1. Create `src/i18n/<code>.ts` typed as `Dictionary` (copy `en.ts`, translate values).
2. Add the locale to `locales` and `localeNames` in `config.ts`.
3. Register it in `dictionaries` in `index.ts`.
4. Add an option in `LanguageToggle.tsx`.

## Tests

`src/i18n/i18n.test.ts` verifies: default is `ms`, key parity between `ms`/`en`,
no "anda" in Malay, nested lookup, interpolation, and missing-key fallback.
